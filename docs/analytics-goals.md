# Цели Яндекс.Метрики

Счётчик 113068094. Цели отправляются из браузера (`reachGoal`), только тем посетителям, кто нажал «Принять» в баннере cookie; тем, кто выбрал «Только необходимые», ничего не уходит. Поэтому цифры в Метрике — по согласившимся, а не по всем. Параметров у целей нет, кроме двух закрытых списков: `kind=lila` у PDF Лилы и `product` (`matrix`, `compat`, `lila`) с необязательным `error` (код из известного списка или `unknown`) у `checkout_redirect` и `checkout_error`. Ни дат, ни намерений, ни почты, ни номеров покупок. Список целей в коде — `apps/web/src/lib/analytics.ts` (`GOALS`), срабатывание проверяет `e2e/goals.spec.ts`.

Создавать в кабинете: Метрика → «Цели» → «Добавить цель» → тип «JavaScript-событие» → идентификатор цели из таблицы.

## Воронки (составные цели Метрики, до 5 шагов)

1. **Разбор матрицы:** `matrix_calculated` → `report_offer_view` → `report_offer_click` → `report_paid` → `report_opened`.
2. **Разбор из совместимости:** `compat_calculated` → `compat_offer_view` → `compat_offer_click` → `report_paid` → `report_opened`. `report_paid` общая для обоих входов, различаются началом цепочки.
3. **Лила с проводником:** `lila_offer_view` → `lila_offer_click` → `checkout_redirect` → `lila_paid`. Бесплатная партия — отдельная цепочка `lila_start` → `lila_finish`: начало обычной партии не шаг покупки проводника, поэтому в составную цель продажи его не включать. Гость, который идёт ко входу, виден по `lila_login_click`; после входа он возвращается на тот же экран и проходит цепочку заново (вход и оплата проходят на чужих страницах). Старт платной партии отдельной целью не отмечается: продажа считается по подтверждённой оплате, а не по запуску игры.
4. **Возвращаемость:** `taro_draw` и повторные визиты (отчёт «Повторные визиты» или сегмент по целям).

Покупка считается по статусу, который подтвердил сервер (`report_paid`, `lila_paid`), а не по клику. Цели «оплачено» ставятся через `reachGoalOnce`: отметка «уже отправлено» записывается в `localStorage` только когда счётчик принял цель, а если счётчик ещё не создан, цель ждёт его до 10 секунд. Без согласия на cookie счётчика нет и цель не уходит; если человек согласился позже этих 10 секунд, цель теряется. Отметка хранится в браузере: если открыть старую страницу оплаты в другом браузере, `lila_paid` и `report_paid` могут засчитаться повторно. Поэтому клиентские цели — не реестр продаж. `checkout_redirect` перед уходом на оплату ждёт отправки цели не дольше 300 мс. Вход через VK ID и оплата на странице ЮKassa проходят на чужих страницах, цели между ними не ставятся.
