# Цели Яндекс.Метрики

Счётчик 113068094. Цели отправляются из браузера (`reachGoal`), только тем посетителям, кто нажал «Принять» в баннере cookie; тем, кто выбрал «Только необходимые», ничего не уходит. Поэтому цифры в Метрике — по согласившимся, а не по всем. Параметров у целей нет (кроме `kind=lila` у PDF Лилы): ни дат, ни намерений, ни почты. Список целей в коде — `apps/web/src/lib/analytics.ts` (`GOALS`), срабатывание проверяет `e2e/goals.spec.ts`.

Создавать в кабинете: Метрика → «Цели» → «Добавить цель» → тип «JavaScript-событие» → идентификатор цели из таблицы.

| `login` | вернулись на сайт после входа через VK ID | вход |

| `report_offer_click` | гость нажал «Войти и купить разбор — 390 ₽» или вошедший отправил форму покупки с верным e-mail | продажа разбора |

## Воронки (составные цели Метрики, до 5 шагов)

1. **Разбор матрицы:** `matrix_calculated` → `report_offer_view` → `report_offer_click` → `report_paid` → `report_opened`.
2. **Разбор из совместимости:** `compat_calculated` → `compat_offer_view` → `compat_offer_click` → `report_paid` → `report_opened`. `report_paid` общая для обоих входов, различаются началом цепочки.
3. **Лила с проводником:** `lila_start` → `lila_offer_click` → `lila_paid` → `lila_finish`. Отдельной цели «предложение показано» нет: оно стоит на том же экране, что и старт.
4. **Возвращаемость:** `taro_draw` и повторные визиты (отчёт «Повторные визиты» или сегмент по целям).

Покупка считается по статусу, который подтвердил сервер (`report_paid`, `lila_paid`), а не по клику. Вход через VK ID и оплата на странице ЮKassa проходят на чужих страницах, цели между ними не ставятся.
