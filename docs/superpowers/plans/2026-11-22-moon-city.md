# Лунные страницы для города человека — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Человек один раз выбирает город, и «Луна сегодня», лента раздела и календарь месяца показывают его восход и заход, лунные сутки, «сегодня» и время событий; адреса, мета-теги и тексты для поиска остаются московскими.

**Architecture:** Ядро расчёта Луны (`packages/core/src/moon`) принимает место `{ latitude, longitude, zone }` (по умолчанию Москва, результат для Москвы не меняется). Страничные сборщики (`buildMoonToday`, `buildMonthPage`) принимают место и форматируют время в его зоне. Выбор города хранится в `localStorage` (`moon:place:v1`) и читается через маленькое внешнее хранилище; пересчёт идёт в браузере, движок и тексты подгружаются динамическим `import()` только после выбора города.

**Tech Stack:** Next.js 16 (свои правила: перед кодом прочесть `apps/web/node_modules/next/dist/docs/`), React 19, TypeScript, vitest (среда `node`: компоненты проверяются `renderToStaticMarkup`, логика — чистыми функциями), `astronomy-engine` через `@oracle/core/moon`, `Intl` для часовых поясов.

**Spec:** `docs/superpowers/specs/2026-11-22-moon-city-design.md`. Нужные куски проекта раздела: `docs/superpowers/specs/2026-11-22-moon-section-design.md`.

## Global Constraints

- Выбор города только для самого человека; отдельных адресов по городам нет; `<h1>` с датой, мета-теги, JSON-LD, FAQ и тексты для поиска остаются московскими.
- Результат для Москвы **побайтно совпадает** с нынешним в окне страниц (предыдущий месяц, текущий и 13 следующих); для давних дат совпадения не требуется.
- На сервер уходит только поиск города (`/api/cities`), как в натальной карте. Координаты и выбор города не уходят ни на сервер, ни в Метрику; новых целей Метрики нет.
- Движок расчёта и тексты суток, фаз и знаков не попадают в первоначальную загрузку страниц: подгружаются динамическим `import()` после выбора города или при сохранённом городе.
- Без автоопределения места и геолокации: только явный выбор.
- Привычка (заходы, серия, награды, гравюры: `moon:visits:v1`, `moon:seen:v1`, `moon:rewards:v1`, `moon:fresh:v1`) продолжает считаться по Москве; ключи и модуль `lib/moon-visit.ts` не меняются.
- Выбор «Москва» стирает запись `moon:place:v1`; сохранённая зона, которую браузер не знает (`new Intl.DateTimeFormat("ru-RU", { timeZone })` бросает), игнорируется как испорченная запись.
- Если Луна за сутки не всходит или не заходит, восход или заход показываются как «—»; номера суток не пропускаются и не удваиваются; отката на Москву нет.
- Месяц календаря задаёт адрес; выбор города пересчитывает **тот же месяц** по зоне города, без редиректа и соседних месяцев; вкладка «Календарь» ленты по-прежнему ведёт на текущий месяц по Москве.
- Слова-оценки дней запрещены (`FORBIDDEN_MOON_WORDS` из `@oracle/content/moon`); нет давления и обещаний.
- Данные только в браузере; внешних шрифтов, CDN и скриптов нет; цвета только переменные `:root`; движение только внутри `@media (prefers-reduced-motion: no-preference)`.
- Мобильные 375 px: без горизонтальной прокрутки страницы, текст не мельче 14 px, зоны нажатия не меньше 44 px, контраст AA, фокус виден; окно выбора города помещается на 375 px.
- Натальная карта не меняется: её тесты (`CityField`, `NatalForm`) остаются зелёными без правок.
- Политику данных и тексты документов не трогать. Коммиты: conventional commits на английском. Мерж только владелица. Перед сдачей каждого PR: `pnpm typecheck` и `pnpm test`.

## Review Focus

1. Сутки, в которые часы переводят (Берлин, 28 марта 2027: 23 часа; 31 октября 2027: 25 часов): первое число месяца, границы суток и «полдень дня» считаются по зоне, а не прибавлением 24 часов. Тест на границу месяца в Берлине.
2. Выбор города, у которого зона — неизвестная браузеру строка или не строка (повреждённый `moon:place:v1`: не JSON, не объект, широта 999, зона `"Mars/Base"`): состояние «город не выбран», страница работает как для Москвы.
3. Медленный или упавший расчёт: пока движок грузится или `import()` упал, человек видит московские данные сервера и чип с городом, без ошибки на странице.
4. Выбор другого города сразу после первого: ответ устаревшего расчёта не должен перезаписать результат нового (гонка).
5. Закрытое хранилище (`getItem` и `setItem` бросают): выбор действует до перезагрузки страницы, без исключения; перезагрузка возвращает Москву.
