## Часть A. Лунный календарь в sitemap (быстрый код, 1 PR)

### Проблема

~457 страниц дней + 15 месяцев занимают ~45% sitemap. Дальние дни 2027 почти не дают трафика сейчас, но едят crawl budget. Вебмастер всё ещё держит снимок sitemap на **198 URL** с 9 октября.

### Решение

В `PUBLIC_PATHS` / `lunarDayPaths` для **sitemap** отдавать только:

| Что | Правило |
|---|---|
| Месяцы | как сейчас: окно 15 месяцев (`monthWindow`) |
| Дни | **только ±30 дней от «сегодня» по Москве** (или текущий + следующий месяц целиком — выбрать одно в PR) |
| Страницы дней вне окна | остаются по URL (ISR/404 по текущим правилам окна месяцев), но **не в sitemap** |

Файлы:

- `apps/web/src/lib/lunar-calendar-paths.ts` — функция `lunarDayPathsForSitemap(now)` рядом с `lunarDayPaths`
- `apps/web/src/lib/seo.ts` — в `PUBLIC_PATHS` для карты сайта использовать урезанный список **или** фильтровать в `app/sitemap.ts` (как с `NOINDEX_DOCUMENT_PATHS`)
- тесты: `sitemap.test.ts`, `moon-year-paths` / lunar paths tests
- smoke в `deploy.yml` не должен требовать дальние дни

Ожидаемый эффект: sitemap ~1037 → примерно **600–650** URL (−400 дней).

### Не делать в этом PR

- не `noindex` на дни (ссылки из месяца и «сегодня» должны оставаться рабочими);
- не сужать окно месяцев без отдельного решения.

### Приёмка

- [ ] unit: в sitemap нет дня дальше чем N дней от Москвы
- [ ] месяц и «сегодня» в sitemap
- [ ] страница дальнего дня из окна месяцев по-прежнему 200
- [ ] после выкладки — ещё раз «Переобойти» sitemap в Вебмастере (или ждать плановый обход)

## Часть B. Карты Таро и LOW_QUALITY (контент + структура)

### Проблема

Яндекс снял десятки `/taro/karty/*` как LOW_QUALITY. Объём текста (~1300 слов) достаточный — бьёт **серийность**: один каркас, title «Карта Таро X — значение…», одинаковые блоки на 78 URL.

План от 12.11 уже добавил блок «В каких раскладах…» — этого мало против массового снятия.

### Стратегия (не удалять колоду)

Оставить все 78 адресов живыми (карта дня, расклады, внутренние ссылки). Менять **сигнал качества и sitemap**, не ломая продукт.

### Этап B0 — измерить (1 день, без кода)

В Вебмастере → «Исключённые» / примеры снятий: сколько карт Таро сейчас вне поиска. Зафиксировать список из 10 старших арканов и 5 младших для пилота.

### Этап B1 — sitemap и хабы мастей (код, 1 PR)

1. На `/taro` уже есть каталог — усилить 4–5 **хабов мастей** (или один хаб «Все карты» с якорными секциями), если их ещё нет как отдельных сильных входов.
2. В sitemap временно оставить:
   - `/taro`, `/taro/karta-dnya`, `/taro/rasklady` + все расклады;
   - **22 старших аркана** карт;
   - младшие — **либо** по 1–2 представителя масти, **либо** все, но после B2 (решение после пилота).
3. Младшие, убранные из sitemap, без `noindex` на первом шаге (как дни Луны): адрес жив, робот меньше сам их просит.

Рекомендация для первого PR: **в sitemap только 22 старших + хабы/расклады**; 56 младших — только по ссылкам из каталога и раскладов.

Файлы-ориентиры:

- `apps/web/src/lib/seo.ts` / `sitemap.ts`
- `apps/web/src/lib/taro-paths.ts`, каталог `TaroCatalog`
- тесты `seo.test.ts`, `sitemap.test.ts`, e2e launch/site-audit

### Этап B2 — пилот уникальности (контент, 10 карт)

Для пилота (например: Шут, Маг, Жрица, Императрица, Император, Иерофант, Влюблённые, Колесница, Сила, Отшельник):

Добавить **уникальный** блок ~150–250 слов, разный по смыслу на карту, без копипаста каркаса:

- «Чем эта карта не является» / частая путаница с соседней;
- 1 бытовая сцена (без предсказаний);
- связь с одним раскладом или с картой дня;
- внутренняя ссылка на матрицу/аркан, если есть мост (`TaroMatrixBridge`).

Тексты — в `packages/content/tarot/`, после правки `pnpm content:build`, приёмка владелицы как у других партий.

Проверка шаблонности: тот же скрипт обхода, что в плане 12.11 (фразы из 6 слов) — доля «общего с половиной группы» у пилота должна упасть.

### Этап B3 — решение по младшим

Через 2–3 недели после B1+B2:

| Если | Тогда |
|---|---|
| Старшие стабильно в поиске, LOW_QUALITY по Таро меньше | Раскатать уникальные блоки на остальные карты партиями по 10–14 |
| Младшие всё ещё сыпятся | `noindex, follow` на слабые младшие **или** держать вне sitemap дольше |
| Хабы мастей дают показы | Вложить усилия в хабы, не в длинный хвост |

### Этап B4 — Лила и арканы матрицы (после Таро)

Не параллелить с B1–B2, чтобы не смешивать сигналы:

- Лила: продолжать этап 2 плана 12.11 (уникальные поля клеток).
- Арканы матрицы: уникальный блок «где встречается в расчёте» + связь с калькулятором (уже есть учебный пример — усилить отличия плюс/минус).
