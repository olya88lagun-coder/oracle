# Лунные страницы для города человека

Дата: 22 ноября 2026. Статус: проект на согласование владелицей.

## Зачем

Все лунные страницы считаются «по Москве»: восход и заход Луны, границы и номера лунных суток, «сегодня». Человеку из Новосибирска, Калининграда или Алматы они дают чужие цифры, и ему трудно им верить. Нужно, чтобы человек один раз выбрал свой город, и «Луна сегодня», лента раздела и календарь месяца показывали его время.

## Что решила владелица

- Выбор города только для самого человека. Отдельных адресов по городам (`/luna-segodnya/novosibirsk`) не делаем: адреса, мета-теги, тексты для поиска остаются как сейчас.
- Выбор действует на «Луну сегодня», ленту раздела и календарь месяца.
- Подход А: пересчёт в браузере. Расчёт на сервере по городу и смешанный вариант отклонены.

## Цели, не-цели, анти-цели

Цели
- Выбрав город, человек видит у себя восход и заход Луны, номер и границы лунных суток, свою «сегодняшнюю» дату и время событий (полнолуние в 17:54 по Москве становится 21:54 в Новосибирске) в «Луне сегодня», ленте и календаре месяца.
- Выбор запоминается в браузере и действует при следующем заходе.
- Без выбора всё работает как сейчас (Москва).

Не-цели
- Автоопределение места: геолокация и IP не используются.
- Города на других лунных страницах (`/luna/...`, фазы, события года, «Дни недели»): они остаются «по Москве», как сейчас.
- Отдельные адреса и тексты по городам.

Анти-цели
- Координаты или выбор города уходят на сервер или в Метрику (сервер видит только поисковые запросы к `/api/cities`, как в натальной карте).
- Расчёт для Москвы с городом по умолчанию и серверный расчёт для Москвы дают разные числа.
- Тяжёлый движок расчёта попадает в первоначальную загрузку страниц.
- Слова-оценки дней (`FORBIDDEN_MOON_WORDS`) и обещания.

## Ограничения

Из `AGENTS.md`: данные только в браузере, никаких сторонних доменов, мобильные 375 px без горизонтальной прокрутки, зоны нажатия не меньше 44 px, шрифт не мельче 14 px, контраст AA, движение только внутри `prefers-reduced-motion: no-preference`, цвета переменными. Политику данных и тексты документов не меняем: на сервер уходит только поиск города, как в натальной карте. Мерж делает владелица.

## Подходы

1. **А. Пересчёт в браузере (выбрано).** Расчёт Луны принимает место (широта, долгота, часовой пояс); браузер после выбора города подгружает движок и пересчитывает видимое. Сервер отдаёт Москву.
2. Б. Расчёт на сервере по городу. Выбор города уходит на сервер и в журналы, нужна правка политики, кеш дробится по городам. Отклонено.
3. В. Смесь (сервер для «сегодня», браузер для календаря). Два пути расчёта. Отклонено.

## Дизайн

### Ядро расчёта (`packages/core/src/moon`)

- Место `Place = { latitude: number; longitude: number; zone: string }` (IANA-зона вроде `Asia/Novosibirsk`); `MOSCOW` остаётся местом по умолчанию (`Europe/Moscow`). Сегодня `Place` содержит `utcOffsetMinutes` и тип не экспортируется; он заменяется на новый, смещение считается на нужный момент через `Intl` (в других странах бывает летнее время).
- `moscowDayStart` обобщается до `dayStart(at, place)`: начало суток по зоне места. `moonRises`, `moonSets`, `lunarDay`, `moonMonth`, `moonSnapshot` (только точка полудня суток) принимают `place`; по умолчанию Москва, и результат для Москвы **побайтно совпадает** с нынешним (тест).
- Фаза, освещённость и знак Луны в данный момент от места не зависят; от места зависят: границы суток, что считать «полуднем дня», восход и заход, номера и границы лунных суток.

### Данные страниц (`apps/web/src/lib`)

- `buildMoonToday(now, place?)`, `buildMonthPage(year, month, now, place?)` принимают место; подписи времени (`clock`, `momentLabel`, `moscowMinutes` в `lib/moon-stage.ts`) форматируются в зоне места, а не только `Europe/Moscow`. Московские сутки в слагах и ключах дат (`moscowDate`) для хранилища привычки не трогаем: заход считается по Москве, как договорено в проекте раздела.

### Браузерный слой

- Хранилище `moon:place:v1`: `{ id, name, region, latitude, longitude, zone }` одного города; чтение и запись в `try/catch`, мусор игнорируется.
- Контекст `MoonPlaceProvider` и хук `useMoonPlace()` отдают `{ place, setPlace, reset }`; провайдер стоит вокруг лент и страниц, где нужен пересчёт.
- Движок подгружается динамическим `import()`: либо после выбора города, либо при открытии страницы, если город уже сохранён. До готовности видны московские данные сервера; без выбора ничего не подгружается.
- Выбор города: чип в ленте раздела («Москва» / «Новосибирск») открывает окно с полем поиска (клиент `/api/cities` и компонент поля из натальной карты) и кнопкой «Вернуться к Москве». Окно — `role="dialog"`, закрывается по Escape, фокус возвращается на чип.

### Страницы

- **«Луна сегодня».** Плитки «Фаза», «Знак Луны», «Лунные сутки», «Восход и заход», строка «Ближайшая смена», лента на 14 дней и ярлык «По Москве» пересчитываются; когда город выбран, ярлык «По Москве» превращается в «Для города <название>». Заголовок `<h1>` с датой, мета-теги, JSON-LD, FAQ и тексты суток остаются серверными (Москва): поисковики видят прежнее. Если по времени города уже наступила другая дата, рядом с плитками стоит строка «Сейчас в <город> — 23 ноября».
- **Календарь месяца.** После выбора города пересчитываются сетка (номера лунных суток по дням, смены суток), панель выбранного дня (восход, заход), события месяца и их время, кривая и лента знаков; «сегодня» определяется по дате города. Страница по-прежнему собирается заранее для Москвы; пересчёт клиентский (`MoonMonthPlace` вокруг `MoonMonthStage`).
- **Лента раздела.** Данные на сегодня берутся из пересчёта, когда город выбран; чип города стоит в ленте на всех лунных страницах (на страницах, где пересчёта нет, чип показывает выбранный город, а подписи остаются «по Москве» с пометкой).

### Тесты

- Ядро: для Москвы `moonMonth`, `lunarDay`, `moonRises` дают те же числа, что до изменения (снимок на несколько месяцев); для места с зоной без летнего времени (Новосибирск) и с летним (Берлин) границы суток и восход смещаются на ожидаемое; граница суток в 00:00 по зоне.
- Хранилище места: мусор, закрытое хранилище, большой JSON.
- Чистая функция выбора данных (`placeOrDefault`) и подписи («Для города …»).
- Страницы: без выбора города разметка не изменилась; нет слов из `FORBIDDEN_MOON_WORDS`.
- Браузер: выбор города меняет восход и номер суток; перезагрузка запоминает город; на 375 px окно выбора помещается.

## Этапы (три PR по порядку)

1. **Ядро:** `Place` с зоной, обобщение функций, тесты совпадения для Москвы. Страницы не меняются.
2. **Выбор города и «Луна сегодня»:** хранилище, контекст, окно выбора, чип в ленте, пересчёт «Луны сегодня».
3. **Календарь месяца:** пересчёт всей страницы месяца под город.

## Решения автора проекта, не владелицы (проверьте)

- Нет автоопределения города и геолокации: только явный выбор.
- Привычка (заходы, гравюры, награды) продолжает считаться по Москве, чтобы серия не ломалась от смены города.
- Заголовок, мета-теги, разметка и тексты остаются московскими (для поиска), пересчёт только видимых чисел.
- Движок подгружается лениво; пока он грузится, виден московский результат.
- Другие лунные страницы (`/luna/...`, «Дни недели») пока без города.

## Уточнения после проверки проекта

- **Блоки, зависящие от номера суток.** Когда город выбран, и плитка «Лунные сутки», и описание суток под ней, и гравюра, символ и ссылка суток (`/luna/sutki/<n>`) берутся по номеру суток **города**. Тексты 30 суток, 8 фаз и 12 знаков подгружаются в браузере вместе с движком расчёта (отдельный ленивый кусок, только когда город выбран или сохранён). Серверная (московская) версия остаётся для поисковиков и для человека без выбора.
- **«Сегодня» и привычка.** Видимое «сегодня» (плитки, подсветка дня в календаре, строка «Сейчас в <город> — 23 ноября») берётся по дате города. Заходы, серия, награды и гравюры привычки по-прежнему считаются по московской дате (ключи `moon:visits:v1`, `moon:seen:v1` и т. д. не меняются): человек может на несколько часов в сутки видеть дату города, а серия считать московскую; разница не больше нескольких часов, и серия от выбора города не ломается.
- **Что значит «совпадает для Москвы».** Результат для места по умолчанию (Москва) обязан побайтно совпадать с нынешним в окне страниц: предыдущий месяц, текущий и 13 следующих (тест на снимке 2026–2027). Для давних дат (смещение Москвы в 2011–2014 годах) совпадения не требуется. Смещение города считается через `Intl` по зоне на нужный момент.
- **Полярные и «пограничные» города** (Мурманск, Анадырь). Если Луна за сутки не всходит или не заходит, восход или заход показываются как «—» (как сейчас, когда события нет), лунные сутки считаются по тому же правилу «с первого восхода»; номера не пропускаются и не удваиваются. Специального отката на Москву нет. Тест: расчёт для места севернее 66° не падает и номера суток идут подряд.
- **Месяц календаря у города.** Месяц страницы задаёт адрес (окно «−1/+13 месяцев» по Москве не меняется). Выбор города пересчитывает **тот же месяц** по зоне города (первое число начинается в полночь города), без редиректа и без пересчёта соседних месяцев; подсвеченное «сегодня» — по дате города (если эта дата вне показанного месяца, подсветки нет). Вкладка «Календарь» в ленте по-прежнему ведёт на текущий месяц по Москве.
- **Выбор Москвы** сбрасывает сохранённый выбор (запись `moon:place:v1` удаляется, состояние «не выбрано»): движок в этом случае не подгружается. Сохранённая зона, которую браузер не знает (`new Intl.DateTimeFormat(…, { timeZone })` бросает), игнорируется как испорченная запись.
- **Поле поиска города.** Из натальной карты берётся готовый `CityFieldView` и клиент `/api/cities`; тексты поля для лунных страниц передаются параметрами, натальная карта не меняется (тест на неё не должен краснеть).

## Что остаётся строителю

Название файла и формат записи города; точный вид окна выбора и чипа в ленте (по духу ленты раздела); способ перерисовки сетки календаря с новыми данными без мигания; нужна ли отдельная страница-описание «Как считается время» (по умолчанию нет, достаточно строки в FAQ).
