# Совместимость по двум датам — дизайн (план 5)

Дата: 2026-09-30. Продолжает `2026-09-24-oracle-site-structure-design.md` (этап «Совместимость»). Решения владелицы: бесплатный результат строится на матрице двух дат (А); «приглашение» — общая ссылка без данных (Б); аркан пары — новая трактовка + готовые тексты «В отношениях» (А); платный разбор пары не входит в первую версию (Б); PDF бесплатный для всех, собирается сервером без хранения дат (А).

## 1. Что получает человек

Страница `/sovmestimost`: два поля — «Ваша дата рождения» и «Дата рождения партнёра», кнопка «Рассчитать совместимость». Результат считается в браузере и показывается на той же странице:

1. **Аркан пары** — сумма центров двух матриц, приведённая к номеру 1–22 (`reduceToArcanum(E₁ + E₂)`). Иллюстрация существующего аркана, название, трактовка «Союз» (4 поля, п. 3).
2. **Вы и партнёр** — две колонки. Для каждого: личность (A), центр (E), задача (D) с названиями арканов и готовым текстом «В отношениях» каждого аркана.
3. **Где вы похожи и где различаетесь** — сводка по номерам: совпадение арканов в одной и той же точке, общие арканы среди трёх точек у обоих; если совпадений нет — так и пишем. Без новых трактовок, фразы-шаблоны из фиксированного набора.
4. **«Отправить партнёру»** — общая ссылка `https://tvoy-orakul.ru/sovmestimost?utm_source=share&utm_medium=partner` и текст «Давай проверим нашу совместимость по дате рождения». В ссылке нет дат. На телефоне — системное окно «Поделиться» (`navigator.share`), иначе ссылка копируется и появляется отметка «Ссылка скопирована.» (`role="status"`).
5. **«Скачать PDF»** и **«Пересчитать»**.

Даты можно вводить в том же виде, что в калькуляторе матрицы (общий разбор `parseBirthDate`). Одинаковые даты допустимы (близнецы, проверка «самой с собой»). Вошедшему через VK ID своя дата подставляется из портрета (только чтение, ничего не пишется).

## 2. Расчёт

`packages/core/src/compatibility.ts`:

```ts
export type KeyPoint = "personality" | "center" | "task"; // A, E, D матрицы
export type Compatibility = {
  pair: number;                                   // 1–22, reduceToArcanum(Ea + Eb)
  people: readonly [Person, Person];              // Person = { personality, center, task } — номера арканов
  sameAtPoint: readonly KeyPoint[];               // точки, где у двоих один и тот же аркан
  sharedArcana: readonly number[];                // арканы, встречающиеся в трёх точках у обоих (по возрастанию, без повторов)
};
export function calculateCompatibility(a: BirthDate, b: BirthDate): Compatibility;
```

Порядок людей сохраняется («вы» — первый). Аркан пары симметричен: пара (a, b) и (b, a) дают один аркан. Чистая функция на `calculateMatrix`, с тестами (известный пример 18.11.1988: центр 11; симметрия; совпадающие даты; крайние значения года).

## 3. Контент

Новый файл `packages/content/compat-arcana.md` → `pnpm content:build` → `src/generated/compat.json`, отдельная точка входа `@oracle/content/compat` (по образцу `lila`). 22 записи по номеру аркана пары; поля: **Суть союза**, **Что даёт**, **Где стоит присмотреться**, **Вопрос для двоих** (заканчивается «?»). Проверки в сборке: длина полей, стоп-фразы (`findStopPhrases`), полнота (все 22), нейтральный род, «вы». Текст: гипотезы, без предсказаний и обещаний отношений. Черновики пишет Claude, вычитывает владелица (как тексты клеток Лилы). Иллюстрации — существующие изображения арканов (`arcanumImage`), новых не нужно.

Тексты «В отношениях» берутся из существующих файлов арканов (`packages/content/arcana/*.md`, раздел «В отношениях»).

## 4. PDF

`POST /api/compat/pdf` с телом `{ a: "YYYY-MM-DD", b: "YYYY-MM-DD" }`.

- Проверки по порядку: тот же сайт (`isSameOrigin`), лимит по IP (`compatPdfLimiter`, около 6 в минуту; ключ — `clientKeyFromHeaders`), размер тела не больше 1 КБ, обе даты через `parseBirthDate`. Ошибки: 403 / 429 / 413 / 400.
- Сервер считает `calculateCompatibility` заново, строит PDF на `pdfkit` (общие части `pdf-common.ts`: шрифты, обложка тёмная, страницы светлые) и отдаёт как `application/pdf` с `content-disposition: attachment; filename="sovmestimost.pdf"`, `cache-control: private, no-store`, `x-content-type-options: nosniff`.
- **Даты не пишутся нигде:** ни в базу, ни в логи, ни в очереди. В лог при сбое — только «compat pdf failed» без данных. Даты живут в памяти запроса.
- Содержимое файла: обложка (аркан пары, «Совместимость · <дата расчёта>»), трактовка союза, страница «Вы и партнёр», сводка, дисклеймер `DISCLAIMER`, колонтитулы. Дат рождения в файле нет (только арканы), чтобы файл можно было переслать, не раскрывая данные.

## 5. Приватность и документы

- Калькулятор считает в браузере; даты не попадают в адрес страницы. Единственная передача даты на сервер — запрос PDF, и только в момент нажатия; сервер её не сохраняет.
- Политика (`/privacy`): в перечне «какие данные обрабатываются» и в сроках добавляем одну строку: «при сборке PDF совместимости даты рождения двух людей передаются на сервер только на время сборки файла и не сохраняются». Новых получателей нет, согласие при входе не меняется. `LEGAL_VERSIONS.privacy` → следующая версия, дата PR.
- Пользователь вводит дату партнёра сам. Текст-подсказка под полем: «Дата партнёра нигде не сохраняется».

## 8. Проверки

- `packages/core`: тесты расчёта (§2).
- `packages/content`: проверки сборки текстов; тест полноты 22/22.
- `apps/web`: тест маршрута PDF (лимит, чужой сайт, плохие даты, размер тела, отсутствие дат в ответе и логах), тест построителя PDF, тест сводки «похожи/различаетесь», тест ссылки приглашения (нет дат), покрытие ≥ 80 %.
- e2e (телефон): вводит две даты → видит аркан пары; ссылка «Отправить партнёру» без дат; PDF отдаётся (`%PDF-`); нет горизонтальной прокрутки; дат нет в адресной строке.
- Полное двойное ревью не требуется (нет оплаты, хранения данных и игровой логики), но маршрут PDF проходит самопроверку по списку безопасности (origin, лимит, размер, логи).
